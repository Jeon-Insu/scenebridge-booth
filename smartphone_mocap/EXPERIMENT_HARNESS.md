# 배치·동적 실험 하네스

2026-09-15 변경. 기존 배치 편집 도구는 유지하며 힘·던지기·질량/마찰 변경 요청에는 `ExperimentPlanner`를 사용한다.

## 역할과 실행 순서

1. 최신 스냅샷과 해당 대화의 최근 기록을 읽는다. 객체 물성은 캐시를 재사용한다.
2. 동적 실험 요청에서 명시한 힘(N)에 지속 시간이 없으면 `needs_clarification`으로 질문한다. 실행이나 부분 배치 변경은 보내지 않는다.
3. 모델은 `plan_experiment(changes=...)`로 요청한 객체의 변경만 작성한다. 전체 참가 객체 목록을 다시 작성하지 않는다.
4. 코드가 변경 전 실험을 복사하고 변경 목록을 검증한다. 이동·접촉 위치를 먼저 계산한 뒤 변경된 목표 위치로 힘/충격량/속도 벡터를 계산한다.
5. 검증을 통과한 실험 전체를 한 번에 `physics_preview`로 전달한다. 기존 참가 객체는 유지한다. 새 실험은 현재 보이는 객체의 물성이 모두 준비되어야 한다.
6. 세팅 요청은 일시정지 상태로 준비한다. 실행 요청은 검증 후 `control_physics(play)`를 전달한다. 실행 여부와 접촉 결과는 Isaac 응답으로 판단한다.

`queued_for_isaac`는 실행 성공이 아니다. `get_experiment_result`는 현재 런타임 결과를 조회한다. QA, 배치, 실험은 별도 모델 프로세스가 아니라 요청별 도구·정책 분기다.

## 변경 계약

- `translate`: 테이블 축 기준 방향, 거리, 단위. +X 동쪽, +Y 북쪽, +Z 위쪽.
- `support: table`: 회전·스케일을 반영한 형상 최저점을 테이블에 접촉시킨다. 사용자가 접촉 배치를 요청한 경우에만 적용한다.
- `dynamics`: `force`(N), `impulse`(N·s), `velocity`(m/s). 힘은 지속 시간 필수. 대상 ID가 있으면 대상 방향이 우선하며 수평 벡터로 변환한다.
- `properties`: 요청한 질량, 마찰, 반발계수, 정적/동적 상태의 실험 한정 변경.
- 힘을 받는 객체의 이전 운동 입력은 새 입력으로 교체한다. 나머지 객체의 위치·회전·스케일·물성·운동 입력은 보존한다.
- 기존 물성 캐시를 `prepare_physics(update_existing=true)`로 덮어쓰는 경로는 동적 변경 요청에서 차단한다.
- 동적 요청에서 저수준 `configure_experiment` 호출은 차단한다. 동일하게 실패한 인자 재호출은 중단한다.
- 정성적인 던지기는 모델이 예시 속도를 선택할 수 있으나 가정과 단위를 사용자에게 표시해야 한다. 특정 충돌 결과를 보장하지 않는다.

## 사용 예

> 화분을 테이블에 닿도록 서쪽으로 10cm 옮기고, 책을 화분 방향으로 0.1N의 힘으로 1초 동안 움직이는 실험을 세팅해줘.

준비 응답 후:

> 실행해줘.

완료 후:

> 실험 결과에서 책이 화분과 충돌했는지 확인해줘.

시간을 생략하면 질문이 나온다. 같은 대화에서 `1초 동안`이라고 답하면 원래 배치 요청을 합쳐 새 스냅샷 기준으로 계획한다. 대화 초기화 후에는 이전 질문을 이어받지 않는다.

## 현재 한계

- 자동 후속 답변 결합은 힘의 지속 시간에 대한 짧은 답변부터 지원한다. 다른 모호한 조건은 질문할 수 있지만 일반적인 슬롯별 답변 병합은 아직 구현하지 않았다.
- 복합 문장의 수치·방향 검사에는 규칙 기반 검증을 사용한다. 여러 대상에 서로 다른 방향/힘을 주는 복잡한 요청은 의미 검증의 확장이 필요하다.
- 동적 변경 도구의 이동은 테이블 축 방향 이동이다. 회전·스케일은 기존 배치 도구로 먼저 편집한다. 참가 객체 제거는 이 변경 도구에서 지원하지 않는다.
- 접촉은 현재 자산의 프록시 형상 기준이며 실제 재질·형상 측정의 정확도를 보장하지 않는다.
- 실제 모델 재생 검증은 생성된 호출·실험 설정 검증이다. 물리 엔진에서 재생하고 접촉 이벤트가 기록되는 검증과 구분한다.
